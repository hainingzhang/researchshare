# 经济学研究团队云端文件共享与版本管理方案

本项目旨在为以经济学研究为主的团队，提供一套易上手、低维护成本的云端文件共享与研究版本管理方案。团队成员可以继续使用 macOS 或 Windows 本地电脑和 WorkBuddy，同时在统一的云端空间协作，并保留研究文档与代码的修改历史。

## 项目意义

经济学研究通常同时涉及论文、数据、Office 文件、代码、研究计划和研究笔记。把所有内容都塞进 Git 不适合管理大型数据和二进制文件；只使用普通共享盘，又难以追踪研究计划和代码的修改过程。

本方案采用两类存储，各司其职：

- **共享文件区**：将论文、数据集、Word、Excel、PowerPoint 和共享结果保存在云服务器，通过 SFTP 与 rclone 挂载，让成员在 Finder 或 Windows 文件资源管理器中访问。
- **Git 项目区**：将研究计划、README、文献综述、代码、Prompt 和研究笔记保存在 Gitea 仓库中，记录修改者、时间、提交说明和差异，并支持恢复旧版本。

这样既能让团队共享大型研究资料，也能让重要的研究过程可追溯，而不要求所有成员熟悉 Git 命令或下载整套云端文件库。

## 目标体验

- 使用 Finder 或文件资源管理器浏览云端共享文件。
- 使用 Gitea 网页查看研究项目、README、提交历史和修改差异。
- 在本地 Git 工作目录中编辑研究文档与代码。
- 使用 WorkBuddy 辅助阅读资料、修改研究文件，并按约定执行 Git 工作流。
- 通过独立账号、访问权限和备份保护团队资料。

## 推荐架构

```text
云服务器
├── /data/research/       SFTP + rclone：论文、数据、Office、共享结果
└── Gitea                 Git：项目说明、研究计划、代码、Prompt、笔记

团队电脑
├── Finder / 文件资源管理器 访问挂载的共享文件区
├── 本地 Git 仓库           编辑和版本管理研究项目
└── WorkBuddy              辅助研究与文件操作
```

## 建议实施顺序

1. 在服务器上配置独立成员账号、SSH Key、共享目录和权限。
2. 先在一台 Mac 和一台 Windows 电脑上试用 SFTP/rclone 共享盘。
3. 部署 Gitea，并为一个研究项目建立试点仓库。
4. 将需要版本追踪的文档和代码迁入 Git；大型论文和数据继续留在共享文件区。
5. 验证拉取、提交、推送、网页查看历史、备份和恢复流程，再推广到团队。

## 重要约定

- 不建议将大型 PDF、原始数据和 Office 文件放入普通 Git 仓库。
- Git 工作目录应保存在本地磁盘，不要放在 rclone 挂载目录中。
- rclone 挂载是远程访问方式，不等于完整离线同步；网络断开时远端文件可能不可用。
- 普通共享盘不适合多人同时编辑同一份 Office 文件；应避免并发覆盖。
- 云服务器本身不等于备份。共享文件区和 Gitea 数据都应有异地备份，并定期验证恢复。
- 每位成员使用独立账号；按最小权限原则管理服务器与 Gitea 访问权限。

## 项目范围

本仓库提供架构方案、三角色部署指南、macOS/Windows 客户端脚本和服务器管理员脚本。客户端脚本可简化 rclone、SSH Key 与 SFTP 的本机配置；服务器脚本可辅助初始化共享目录并逐个授权成员，但管理员仍需负责审核 SSH、防火墙、账号和权限。脚本尚未在目标 Ubuntu 服务器和各版本 Windows 电脑上进行端到端验证。实际部署时，应结合团队规模、服务器配置、数据敏感性和网络环境调整权限、备份、缓存及安全策略。
